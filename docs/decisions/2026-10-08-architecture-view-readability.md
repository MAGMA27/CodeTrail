# 决策：固定快照架构画布的可读层级

Status: proposed

## 问题

职责与支持目录混在同一首层排列，展开多个大组会同时摊开模块关系；平铺依赖层级也会让折线穿过其他容器。用户截图还显示 3 列容器图在实际固定索引上存在可读性和边路由问题。架构图必须保留既有概览和证据边界，不能通过新增解析、改关系契约或不画却宣称完整解决。

## 决定

仍直接投影 `ProjectOverview`，不增加 API、持久化视图状态或运行依赖。默认先显示职责与未归属业务目录；测试、fixture、docs、examples、benchmarks 等辅助目录基于通用路径片段语义归类并默认收起。只展开一个职责/目录组，容器间关系始终连到容器；组内关系总数保留在容器，模块间边默认汇总，用户悬停或键盘聚焦模块时只显示该模块当前画布返回的真实相邻边，并显示计数。

职责或目录聚焦只保留所选分组与当前过滤下的一跳入/出邻居，不显示邻居彼此的边。所选职责置中，入向邻居排在左侧、出向邻居排在右侧；双向邻居只放置一个节点，并保留两个方向的已返回关系。聚焦边利用列间空白和方向匹配的容器中心端口，不建立通用避障路由引擎。非聚焦首层继续按真实依赖方向分层，并保留真实循环组，同层显示和计数。

模块关系钻取临时隐藏架构画布、在同一主图承载，不再并列两个复杂画布；返回时恢复之前的展开和聚焦状态。普通模块关系图按每行容器的最高高度推进下一行，父目录子节点使用相对坐标和 parent containment。

计数只表示当前固定快照和当前画布实际收到的数据。范围外邻接、总览/关系截断、未解析关系和规则未识别状态继续分开提示，不能用空结果断言不存在依赖。

总览容器依赖采用方向居中的直线；穿过其他容器及安全边距的关系仅在当前画布折叠，显示数量与聚焦入口，不改变索引或聚合计数。职责和实际可显示的源码目录均可聚焦一跳依赖，目录不会伪装成职责；已被 manifest 完全归属的重复目录不提供假聚焦入口。模块悬停只改变边的显示，不插入会推动画布的提示段落；相邻关系数量保留在模块提示中。

## 替代方案

- 默认显示所有辅助目录和所有组内模块边：增加首层节点和文字/线路密度，展开大组时难以分辨主职责。
- 聚焦时继续显示邻居之间的关系：多出路径不会扩大所选职责主路径，且边更容易穿过中间容器。
- 为任意边建设通用避障路由器：复杂度超出当前实际问题；所选职责居中、邻居分列后，关系可走列间空白。
- 删除或改写原始关系、为布局生成传递边：会混淆静态事实与显示投影，计数和证据不再对应固定快照。
- 把模块关系图作为第二幅常驻画布：进一步压缩架构图和证据上下文，并使返回状态更难保持。

## 验收与证据

布局和目录聚焦的自动回归通过；固定自用快照已在实际 1440×900 / 1366×768 视口查看总览及展开。鼠标与键盘模块钻取、源码读取和返回恢复均有实际证据；独立密集 fixture 与所有组内临时边尚未遍验，保留 proposed 状态。详细命令、截图工具输出和失败限制见本地阶段记录；不能由局部结果推定所有密集图可读。

## 后果

布局是有限职责依赖图的可读投影，不承诺任意图零交叉；用户可平移缩放查看超出视口的容器。默认的容器边和模块详情仍只表示已返回的静态事实，辅助目录归类依赖路径片段约定。复杂目录模式、关系预算或规则未识别都可能令当前画布部分显示，诊断必须保留相应限制。
