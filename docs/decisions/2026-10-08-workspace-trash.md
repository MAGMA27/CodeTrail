# 决策：Project 与 Session 可恢复回收站

Status: implemented

## 问题

工作区导航需要移除不再常用的 Project 和 Session，同时保留来源、固定索引、消息、Run、报告与证据。移除和恢复必须跨服务重启生效，并阻止普通读取、写入和自动注册重新显示已移除对象。

## 决定

在现有 Project/Session SQLite 行增加可空的移除时间，采用软移除，不物理删除任何来源、索引或调查数据。正常列表和作用域操作只接受未移除对象；HTTP 提供回收站列表、移除及显式恢复，所有操作继续复用 WorkspaceService 和 Pydantic 契约，不为 MCP 增加写权限。

Project 移除会隐藏其所有 Session 和固定索引；恢复 Project 只恢复 Project 自身，独立移除的 Session 仍保持移除。Session 移除只隐藏该 Session，不改变其消息、Run、报告、证据或固定 index。存在活动 Run、导入或索引更新时拒绝移除并返回可重试冲突。旧库通过幂等列迁移升级。

## 替代方案

物理删除会破坏用户明确要求保留的索引与调查证据；仅在前端隐藏不能阻止服务端读取、写入或自动注册重新创建状态。单独复制回收站数据库会增加跨库生命周期和恢复一致性问题，因此复用现有 Project/Session 行。

## 验收与证据

隔离临时数据目录下，API、存储与 Run 相关回收站测试 53 项通过，覆盖旧数据库迁移、项目/Session 移除与显式恢复、独立 Session tombstone、消息保留、HTTP 作用域与重复恢复、重启持久化、legacy/managed 项目不自动复活、活动 Run/导入/索引更新保护及移除后的查询/写入拒绝；功能生成与 MCP 回归另有 31 项通过。`pnpm contracts:check` 的 29 项契约测试通过。Web typecheck、67 项 Web tests 和生产构建通过，`next-env.d.ts` 已按原 SHA-256 恢复。就近文档检查通过。

实际浏览器已复现架构容器展开后 hover 模块仅强调相邻边，节点位置稳定，点击钻取并返回保留展开状态。独立 localhost:3000 标签确认回收站入口与 Project/Session 控件可见；打开列表时当前运行的旧 API 返回 404，无法在不重启用户服务的前提下完成在线列表与恢复流程，故这部分 UI 流程仍未验证。未对浏览器中的现有项目或 Session 执行移除/恢复。

## 后果

回收站状态随现有项目索引库持久化；恢复依赖原索引库仍可访问。该阶段不提供永久删除、保留期清理或回收站批量操作。
