# 决策：工作台管理服务端模型配置

Status: implemented

## 问题

真实功能识别和 Issue Run 依赖服务端 `config.json` 中的模型密钥；当前工作台没有读取或更新该配置的入口，用户无法在使用前补齐配置。

## 决定

模型配置继续由 API 数据目录中的 `config.json` 所有。工作台通过脱敏 GET 和受限写接口管理配置；读取响应只返回密钥是否存在，留空保留密钥，单独的移除标记才清除。有 Origin 的写请求必须来自配置的 Web Origin，无 Origin 的本地 CLI 请求仍可写入。base URL 校验有效的绝对 HTTP(S) URL 并拒绝 userinfo，provider/model 去除首尾空白且拒绝空值。每个 Registry 在同一锁内读取、合并并原子写入配置，避免并发空 key 更新覆盖新 key。API 与 MCP 的新模型任务读取共享文件；每个 Run 在创建时捕获模型配置，避免更新影响运行中的任务。保存不试连供应商、不发送源码，不增加 MCP 写工具。

## 替代方案

不将密钥保存在浏览器或前端环境变量中，避免浏览器存储和构建产物成为配置所有者。继续要求用户手工编辑文件则无法闭合普通工作台首次使用路径；单独新增 MCP 写工具会扩大未请求的能力边界。

## 验收与证据

自动化覆盖 GET/POST 脱敏、空值保留、明确移除、原子写失败保留旧文件、loopback/Origin 边界、并发更新、API/MCP 共享文件的新任务读取、Run 配置冻结和契约。隔离 UI 验证保留/移除和密码框清空；当前 3000/8000 实际 UI 验证读取配置、编辑入口和未配置时功能 CTA 直接打开设置而未提交模型请求。实现、自动验证和独立 UI 验收完成，决策状态标记 implemented。真实供应商连通性与模型效果未测，保存本身不试连供应商。

## 后果

保存成功只证明配置已持久化，不证明供应商地址或密钥可用。已有 MCP 会话无需 reload；每个新 real 任务重新读取配置，活动 Run 保留内存中的原配置快照。
