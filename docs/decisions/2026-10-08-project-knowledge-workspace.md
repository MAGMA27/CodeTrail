# 决策：项目知识采用画布与按需详情工作区

Status: implemented

## 问题

知识页把架构、全量 HTTP 关联、搜索、入口统计、功能生成/历史与结构详情纵向堆叠，用户需要离开画布寻找选中节点。画布成为长报告的第一段，妨碍打开项目后理解架构的 MVP 主任务。

## 决定

中央默认显示架构并使用剩余高度；知识工具栏明确切换架构与功能。结构、边、HTTP 双端证据、搜索、版本与覆盖在按需右详情中读取，内容独立滚动。源码/外部图面板使用既有全局 panelMode，打开时隐藏本地详情，返回恢复原上下文，避免双右栏。

架构与功能切换保持架构组件挂载，项目/index 的 key 变化重建知识视图。没有新增后端接口、持久化状态或依赖，也没有自动生成项目功能。当前行为由 [工作台](../../apps/web/workbench.md) 维护。

## 替代方案

仅折叠页面下方区块仍需滚动寻找所选节点，不能解决上下文断裂。额外增加永久详情列会与已有源码证据栏并存并压缩主图，因此采用按需互斥详情。

## 验收与证据

本轮在现有 localhost:3000 的独立 Chrome 标签只读取本项目固定快照：首屏未铺开全量 HTTP 列表；右侧详情独立滚动；架构与功能切换、模块钻取、源码读取及返回架构保留 API 展开，搜索恢复结果与项目切换清理旧详情均实际验证。65 项 Web 测试、类型检查与生产构建通过；共享与本地文档检查通过。固定分辨率矩阵不作为 MVP 交付条件，先前已发生的尺寸观察保留在本地阶段证据。

## 后果

主画布与阅读详情分区；后端概览仍一次返回有界数据，按需展示不等于按需解析。静态依赖和 HTTP 形状仍不证明运行时数据流。功能生成、历史和重试复用原有能力，本轮没有为 UI 验收生成新的用户数据或调用真实模型。
