# CodeTrail 工作区 UI 规范

状态：UI-S2 已实现的工作区规范与验收记录，已包含 P3-I1 Run 报告候选位置与有界静态影响面板，以及 Codex external Run 的自动发现与实时展示边界。本文保留 UI-S1 的设计基线，同时记录生产 `/` 的迁移结果；可浏览原型位于 [apps/web/app/prototype/page.tsx](../../apps/web/app/prototype/page.tsx)，生产组件位于 [apps/web/app/workbench-ui.tsx](../../apps/web/app/workbench-ui.tsx)。

## 设计读法

产品面向 PC 端，当前设计与验收以桌面工作区为范围（用户于 2026-10-06 明确确认）。窄屏、移动端和平板专用适配不作为交付条件；下文既有响应式断点及移动截图仅保留为实现与历史证据，不要求补齐窄屏验收矩阵。

这是给工程师使用的代码理解工作区，核心任务是先建立项目事实，再围绕一个调查主题保留上下文。视觉语言采用冷静、编辑器式的中性界面：正文使用无衬线字体，代码和身份使用等宽字体，单一蓝色强调交互，信息密度中等，避免实验室网格、装饰渐变和营销式卡片堆叠。

本轮设计取值为 `DESIGN_VARIANCE 5`、`MOTION_INTENSITY 3`、`VISUAL_DENSITY 5`。动效只用于按钮按下、面板开关和状态反馈，必须在 `prefers-reduced-motion: reduce` 下退化为即时变化。设计借鉴 Codex 式的项目与会话层级，不复制品牌资产、版本标识或未核实的像素细节。

## 迁移前基线与入口映射

UI-S1 迁移前的生产页是单页纵向工作台，顶部为 `CODETRAIL / INDEX LAB` 和“关系勘验台”，项目、导入、索引、搜索、概览、图和源码证据按纵向区块排列，背景使用深色网格和渐变。它已经承载真实项目、固定索引、导入重试、概览、历史、功能图、代码关系、源码证据和 Session 消息能力，但主导航没有把项目知识与会话分成稳定的空间；UI-S2 已保留这些 API 行为并迁移外壳与信息架构。

| 现有入口或控件 | 目标入口 | 保留的行为 |
| --- | --- | --- |
| 项目列表与项目切换 | 左侧“项目”列表 | 仍按 `project_id` 切换，并清理或忽略旧请求和旧草稿 |
| Session 列表、新建 Session | 当前项目下的“会话”列表和 `+` | 列表按项目隔离；创建后固定服务端返回的快照 |
| “知识页”视图 | 左侧“项目知识”入口、中央知识页 | 不输入 Issue 也能查看入口、功能、模块和版本详情 |
| 功能图、代码关系 | 知识页操作或右侧“功能图”面板 | 图筛选、分组和关系方向仍使用现有受限图结果 |
| 源码检查器、证据链接 | 右侧“源码证据”面板 | 证据仍验证 `project_id`、`index_id`、路径、行范围、hash 和 `evidence_id` |
| 本地/GitHub 导入、索引控制和版本历史 | 唯一项目操作入口“源代码与索引”，页内分“源代码来源”和“固定索引” | 仍分别显示 ImportAttempt、固定 commit、失败/重试状态，以及固定版本、创建/打开和新鲜度控制；失败历史不替换成功版本 |
| 符号搜索 | 知识页工具栏的“搜索”入口 | 搜索仍限定当前 `project_id/index_id`，结果可打开证据 |
| Session 消息追加 | 中央会话页底部输入区 | 当前只保存 human 消息，不展示假助手回复或可用的分析按钮 |

UI-S1 不删除任何现有 API 能力；映射是目标信息架构，UI-S2 已完成生产页面迁移，未改变 HTTP/MCP 契约。

## 应用外壳

### 三栏结构

根容器使用 `min-height: 100dvh`，不使用固定 `h-screen`。顶部全局栏高 `56px`，下方工作区拥有剩余高度。工作区默认三列，右列关闭时宽度为 `0`，打开时通过 CSS grid 使用明确的面板宽度变量。

| 视口 | 左侧项目/会话 | 中央内容 | 右侧面板 | 规则 |
| --- | ---: | --- | ---: | --- |
| `>= 1101px` | `264px` | 默认 `minmax(0, 1fr)`，正文最大 `900px`；代码关系、功能图和影响画布打开时与图面按 `.72fr / 1.28fr` 分配 | 默认 `0px`，源码面板默认 `360px`、可调 `300-440px`；代码关系、功能图和影响画布使用主图分栏 | 左侧常驻；主图与项目/Session 内容并列 |
| `940-1100px` | `236px` | 默认 `minmax(0, 1fr)`；代码关系、功能图和影响画布打开时与图面按 `.72fr / 1.28fr` 分配 | 源码面板打开 `320px`；代码关系、功能图和影响画布使用主图分栏 | 左侧常驻；主图与上下文并列 |
| `768-939px` | `236px` | 中央内容 | 源码面板 `320px`；代码关系、功能图和影响画布覆盖中央区域 | 左侧常驻；主图不压缩为窄侧栏 |
| `< 768px` | 抽屉，宽度 `min(86vw, 304px)` | 单列，水平内边距 `16px` | 全宽底部 sheet，最大 `100vw` | 项目按钮打开抽屉；遮罩关闭；面板打开时不改变会话路由 |

桌面工作区最小高度是 `calc(100dvh - 56px)`。顶部栏只保留品牌、当前项目/区域、原型或真实状态；不堆放导入、索引、Run 等低频动作。生产页的具体状态文案仍由 API 返回状态决定。

### 滚动、折叠和层级

- 左侧导航独立纵向滚动；项目与会话列表不随中央消息滚动。
- 中央项目知识页默认是架构工作区，画布占用工具栏以外的剩余高度；搜索、HTTP 与结构详情在独立滚动的右侧栏按需查看。功能视图独立滚动。会话消息保留原中央滚动容器和底部输入区，不改 Session 行为。
- 左侧导航高度跟随顶部栏以外的工作区，并独立纵向滚动；项目操作标题和关闭入口常驻，表单与索引状态在正文区独立滚动。
- 右侧源码面板和主图拥有独立滚动/画布；从关系图或功能图打开源码后提供返回原图入口，不重置中央滚动位置、会话草稿或当前项目。
- 右侧面板默认收起。知识页通过“打开功能图”、入口/功能行的“查看证据”打开；面板标题提供关闭按钮和“源码证据/功能图”切换。
- 面板宽度滑块只控制源码面板，范围 `300-440px`，步进 `10px`；代码关系、功能图和影响画布共用主图分栏。移动端面板以全宽或底部 sheet 展示。
- `z-index` 只使用外壳层级：移动导航 `5`、遮罩 `4`、证据面板 `6`。不在内容卡片上堆叠任意高层级。

### 项目导航

左侧顶端是“项目”和“新建”，下方每个项目显示名称、来源类型和真实索引状态。展开项目后显示“会话”和 `+`；Session 行显示主题和更新时间，当前行有背景和焦点边框，而不是装饰性彩色点。左侧底部提供“项目知识”和唯一的“源代码与索引”稳定入口。

当前项目没有可用索引时，项目仍可选择，但“项目知识”显示空状态，不能伪造功能图、Run 或分析结果。没有项目时左侧显示“还没有项目”，中央显示空工作区，并提供真实创建/导入入口。

## 页面状态

### 项目知识页

2026-10-08 起，知识页使用“架构 / 功能”切换。默认架构不附加全量 HTTP 列表、搜索结果、功能生成/历史或结构详情到页面底部；这些内容通过工具栏入口、节点/边选择或功能视图读取。右详情与全局源码/外部图面板互斥，源码返回恢复原选择；架构/功能切换保持架构挂载，项目/index 切换重建局部视图。版本与覆盖保留简短入口和部分分析标记，完整诊断按需查看。

当前 PC 的 MVP 阅读闭环是交付条件；不要求固定 1440×900 / 1366×768 分辨率矩阵，历史截图与尺寸记录不删除。

中央顶部显示项目名称、简短说明和当前索引状态，不重复放置导入或索引操作按钮。版本条紧邻顶部内容，展示当前可用 revision 或 snapshot，不把 ID/hash 放进标题；项目操作从左侧唯一的“源代码与索引”入口打开。项目架构视图是知识页首要窗口，直接消费当前固定 `ProjectOverview`，桌面架构画布以 flex 使用中央工具栏以外的剩余高度；结构、入口与 HTTP 关联在右侧独立滚动，功能及历史在功能视图读取。图上分类计数使用可读辅助字号，完整计数仍可通过无障碍标签和悬停提示读取。功能图和代码关系仍是独立图视图，但与影响画布共用主图分栏，不与架构画布混为同一视图。主图分栏时中央架构画布随剩余宽度收缩，HTTP 详情在单列右侧栏读取，项目名称提供完整文本提示。

知识页按以下职责组织：

1. “项目架构”先呈现固定索引的职责和未归属业务源码目录、Python/TypeScript 模块及有向 imports/calls 聚合边；常见测试、fixture、docs、examples、benchmarks 等辅助目录默认收起，可显式查看。HTTP 客户端到 FastAPI 路由的方法/路径形状关联保持独立展示并连接目录容器。容器折叠或展开时均说明已返回组内关系计数；模块间边默认汇总，悬停或键盘聚焦模块后显示其当前画布已返回的相邻关系。选中容器可聚焦边界，节点进入既有符号关系图，代表边先显示依赖详情，由证据按钮打开同一 index 的源码。
2. HTTP 入口是可选筛选视角，突出关联目录而不再画一套互斥子系统；边类型可筛选，关系投影不写回静态图。视图对齐已有 `project_id/index_id`，展开最多 40 个模块，并显示 overview 截断、unresolved 和未映射端点等覆盖边界。
3. “功能”视图展示主要功能和关系来源；覆盖详情保留入口候选统计；静态关系与语义线索有明确文字和样式区别。“项目功能”展示少量主要功能，可逐项打开同一快照的证据。
4. “版本详情”展示 `index_id`、源码 hash、生成模式和限制；详情不抢占首屏主层级。说明条提醒当前覆盖边界；静态 TypeScript 事实和 HTTP 方法/路径形状关联须标明其语法及运行目标限制。

从选中职责可显式进入聚焦视图，保留该职责及当前 imports/calls 筛选下的双向一跳职责/目录；HTTP 形状由独立开关决定是否纳入相邻端点。聚焦先按固定概览里可用的模块归属和关系计算，再应用折叠与 40 模块预算；邻接组初始折叠，隐藏事实计数与服务端截断分别提示。返回项目总览恢复进入前的展开组，切换项目或 index 清空聚焦状态。

职责聚焦画布将选中职责放在中心，入向邻居放左侧，出向邻居放右侧；双向邻居只保留一个节点并显示两向真实边。邻居彼此关系不在聚焦画布展开，作为聚焦范围外计数显示。跨职责关系连接容器，不穿过展开后的模块卡。组内关系计数保留在容器；模块边默认收起，悬停或键盘聚焦模块时突出当前画布中已返回的相邻边并显示计数，计数仍受索引覆盖诊断约束。架构主画布切换到单模块关系图时保留架构组件状态，返回后恢复展开与聚焦前状态。普通模块关系图目录容器依每行最高高度增长，子目录相对父容器定位。

入口、功能、模块和符号都使用稳定 ID 或可追溯的证据链接。图上的可达关系不等于确认影响，测试引用不等于覆盖率，模型推断不升级为静态事实。

总览容器依赖采用方向居中的直线；穿过其他容器及安全边距的关系仅在当前画布折叠，显示数量与聚焦入口，不改变索引或聚合计数。职责和实际可显示的源码目录均可聚焦一跳依赖，目录不会伪装成职责；已被 manifest 完全归属的重复目录不提供假聚焦入口。模块悬停只改变边的显示，不插入会推动画布的提示段落；相邻关系数量保留在模块提示中。

### 会话页

会话页标题栏显示“返回项目知识”、主题和简短固定版本标签；Session ID、Project ID、完整 revision/snapshot 身份收入可展开的详情层。固定版本是当前会话的上下文说明，不允许自动跟随项目最新索引。中央消息区只展示已保存消息、来源、序号和时间。Run 当前状态、失败/取消操作、报告限制和证据入口保持可见；公开执行事件、工具结果与历史列表默认折叠。

输入区固定在中央底部，textarea 最小高 `86px`，支持垂直调整大小。具体行为如下：

| 行为 | 约定 |
| --- | --- |
| `Enter` | 在 `Shift` 未按下且 `event.nativeEvent.isComposing` 为 false 时提交；提交前去除首尾空白 |
| `Shift+Enter` | 插入换行，不提交 |
| 输入法 | composition 期间 Enter 不提交；composition 完成后用户再次按 Enter 才提交 |
| 草稿 | 以 `project_id/session_id` 为键隔离；切换项目或 Session 不带入旧草稿，刷新恢复策略由生产实现决定 |
| 保存中 | 保留 textarea 内容，允许编辑后续草稿；提交按钮和 Enter 禁用重复提交，状态显示“保存中”；不插入本地假消息 |
| 保存成功 | 使用服务端 sequence 和时间追加 human 消息；只有提交时的 project/session/request 和草稿修订仍匹配时才清空当前草稿，否则保留后续文字并回到待保存状态 |
| 保存失败 | 错误紧邻输入区或消息区，未变更草稿保留原幂等键并提供“重试保存”；后续编辑使用新的提交身份，不显示成功或助手状态 |
| 分页 | 当前 API 按 `sequence` 递增返回，消息超过一页时在消息尾部提供“加载后续消息”；空会话不显示无效分页入口，追加新消息不跳到旧消息中间 |

### 证据面板

证据面板顶部固定显示来源上下文：`project_id`、`index_id`、必要时 `generation_id` 或 `session_id`。源码片段显示相对路径、行范围、content hash 和证据类型；打开面板前后中央会话内容、滚动位置和草稿完全不变。返回结果中的任何 project/index/path/line/hash/evidence 身份不一致时显示错误，不回退到当前 latest。

功能图面板的工具栏负责入口、功能、模块和全部筛选；图结果来自当前固定快照的受限接口。面板中可切换到源码证据，节点点击不隐式改变项目或 Session。证据链接不调用模型，已保存结果和历史读取不触发生成。

Run 报告中的 candidate link 或唯一 symbol finding 提供“查看影响范围”入口。影响面板显示报告固定 `index_id` 上的根节点、调用方/被调用方方向、1–2 层深度、静态 `calls` 路径、截断状态和 unresolved 未知边界；root、静态可达和模型候选使用不同文案/图例，不能显示成已确认 Bug 影响。无唯一符号、失败、取消或中断报告显示 unmapped/空态并保留源码 evidence；点击影响节点进入同一节点 snapshot 的源码证据，不回退到当前 latest。

代码理解报告的结果区域在 `outcome=explanation` 时显示“流程解释”和 `complete/partial` 覆盖级别，并按 Agent 提交顺序显示最多 12 个步骤。每步显示 confirmed/inferred/unknown 标识、标题、说明和同报告 evidence 按钮；partial 或 unknown 明确提示未确认环节。步骤只有一个有效 symbol 时提供“进入局部关系图”，多个或没有唯一 symbol 时保留源码入口并说明原因；解释步骤不显示候选影响装饰，也不把解释顺序绘成静态 calls 边。

### 项目操作

唯一的“源代码与索引”入口打开同一个项目操作页，页内用“源代码来源”和“固定索引”两个页签承载不同生命周期的操作。标题与关闭按钮固定在操作页顶部，表单、快照和新鲜度结果在独立滚动正文内可达；单列表单占满内容列宽，不保留空白分栏。“源代码来源”显示本地路径和 GitHub HTTPS 导入表单，说明路径由 API 服务端读取、来源目录只读，并保留 ImportAttempt、固定 commit、失败和重试状态；“固定索引”显示固定版本、失败/部分状态、revision、snapshot hash、新鲜度检查、创建/打开和更新。首次导入成功后服务端仍可建立初始固定快照，已有项目则直接管理其索引快照。页面合并的是入口，HTTP/API 语义仍保持分离。生成模式、预算和模型供应商只放在详情或明确的生成操作中。当前功能识别需用户显式点击并选择源码范围，使用服务端模型；普通界面不提供开发模拟模式，历史模拟结果明确标为演示结果，原型不调用模型。

## 设计 token

目标页使用单一主题的中性浅色 token，同时定义等价的深色 token 以响应系统偏好；不在同一页面分割浅深主题，不使用旧实验室网格或背景渐变。

| 类别 | 规范 |
| --- | --- |
| 背景 | 浅色 `#f7f8fa`，提升层 `#ffffff`，弱层 `#f0f2f5`；深色使用 `#171b22`、`#1d222b`、`#222832` |
| 正文 | 浅色 `#202633`，次级文字 `#687285`，弱文字 `#9aa3b2`；正文对比度按 WCAG AA 验证 |
| 强调 | 全页只用一组低饱和蓝 `#3158d9` 及其状态变体；不使用 AI 紫渐变或多色 CTA |

## 原型与生产边界

独立原型是 `apps/web/app/prototype/` 下的 `/prototype` 路由，使用本地常量和 React 本地状态，故意不导入 `lib/api.ts`，不访问网络、不读取 SQLite、不读取宿主路径、不调用模型、不创建项目或 Session。右上角“预览状态”明确标记仅为设计评审；状态切换和保存延迟是视觉行为演示，不能当作真实 API 验收。

生产 `/` 页面由 `apps/web/app/workbench.tsx` 编排，并由 `apps/web/app/workbench-ui.tsx` 提供视图。现有 API、HTTP/MCP 契约、项目归属、固定索引、证据和 Session 消息规则继续有效；UI-S2 已完成真实页面迁移。生产 Run 面板的 SSE 状态由可测试订阅状态机驱动：有效前进事件才重置重连预算，终态事件或四类终态控制帧结束订阅，有限失败后回退到单一有界轮询；Project/Session/Run 切换、刷新和卸载不得让旧回调写入当前范围。Session history 在外部 MCP 写入后通过有界轮询发现 Codex external queued/running Run，自动载入同一 Run 详情并复用 SSE，不创建第二个 Run 或显示隐藏思维链。P3-I1 影响面板是 Run 报告的只读派生视图，按需请求固定 snapshot 的静态 `calls`，方向/深度改变会取消旧请求并重新读取，不改变 Run、报告或模型状态。迁移后的生产页与原型继续分开验收，截图不能把静态可达、Agent 或真实模型质量标为已确认。
