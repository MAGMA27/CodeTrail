# 审查子系统

读取 docs/development.md、相关子系统页面、需求或决策记录和实际 diff。按逻辑子系统审查；契约变化覆盖相关调用方。优先使用独立上下文；没有独立审查者时明确为自审，不能声称独立通过。

以源码和实际结果重新判断：职责与依赖是否合理；外部输入是否验证；数据是否绑定同一快照；证据是否来自返回结果；静态边与模型假设是否分开；资源、取消、失败和预算语义是否完整；文档是否准确区分已实现与计划。仅展开本次相关问题，不强制引入插件、队列或多 Agent。

按 docs/development.md 选择最小充分验证。文档检查不能证明语义正确，fixture 不能证明真实模型效果，内部单测不能替代用户可见流程。缺少证据标记 UNVERIFIED，实际失败或阻断问题标记 NEEDS_FIX；全部必要验收满足才给 PASS。

使用 docs/templates/review.md 的结构汇报，可直接写在最终回复；仅需要持久审查记录时保存文件。每个问题给出位置、触发条件、后果和修复建议。记录实际命令与结果，不复用旧测试数量作为本轮证据。

只读审查不修改实现。已授权的实现任务中修复发现的问题，必要时回到设计或同步阶段；只复查受影响的结论。尚缺用户决定或外部条件时明确报告，不扩大权限或伪造完成。
